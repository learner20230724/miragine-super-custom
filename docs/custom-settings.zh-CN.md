## 打开、暂停与视角

- **F2 是唯一设置入口**，没有常驻「设置 F2」按钮。宽窗口并排、窄窗口上下排列，游戏保持比例。
- 打开／收起设置**都不改变暂停状态**。按 F2、Esc 或「收起 ×」关闭；有确认框时 Esc 先取消确认，想暂停就手动点暂停。
- 面板顶部「时间」区包含 **0～100 倍、步进 0.1** 的滑块／输入框，以及新增的 50／100 倍快捷按钮及横向暂停／继续按钮。0 是暂停，1 是原速，0.1～0.9 是慢动作；继续恢复此前正倍率。
- 下方独立「视角／显示」区包含自由观察、跟随、全图、全屏和 30／60／120／240 FPS 目标。全图调整镜头，全屏调整窗口，两者不同；F11 同样可切全屏。
- 战场左下角使用清晰可点击文字「暂停游戏／继续游戏」「游戏帮助」「退出游戏」，不再将这些按钮图案放大成模糊文字。

主战场可用左／右／中键拖动；左键超过 5 个 CSS 像素后才开始拖动，自动切入自由观察。小地图、滚轮和 IJKL 保留。U 放大／O 缩小以战场中心为锚点，滚轮仍以鼠标为锚点；参数输入和确认框不触发这些游戏快捷键。有效倍速数字在输入时立即生效；规则数字按 Enter 或离开输入框提交；合法修改自动应用并保存，不再另点「应用设置」。

速度、暂停、显示上限和观察镜头即时生效，不属于规则预设；显示的是目标及实际速率，100 倍／240 FPS 都不是性能保证。

## 页面与生效时机

| 页面 | 内容 | 生效方式 |
|---|---|---|
| 当前战局／基础 | 本局难度摘要 → 生成与清场 → 通用基础规则 → 红蓝当前状态；资源、水晶、当前招募／AI | 数字按 Enter 或离开输入框确认；开关立即生效。当前资源只影响本局；规则同时成为后续新局设置 |
| 兵种 | 同一兵种的红蓝两列独立编辑名称、说明、生命、护甲、两类伤害、移速、射程、间隔、命中延迟、费用、人口、收入 | 确认后自动应用；不会自动改另一阵营。费用等影响后续招募，不退还已支付资源 |
| 开局设置 | 双方开局金币、收入／人口、首轮等待；新局模式和难度；另列「自动行为（本局与下局）」 | 资源／首轮等待／开局人口确认后下局使用，不重置本局资源与倒计时；招募／AI 开关立即生效并保存供后续新局使用 |
| 难度／AI | 按难度与参数分类选择；蓝水晶伤害／间隔、反制概率、阈值、候选集合、克制表与强制选择 | 确认后自动应用；只有本局对应难度生效，其他档留待选用，不会偷偷切换难度 |
| 预设／文件 | 命名预设、导入／导出 | 载入／导入立即应用并保存；另存预设只是命名副本，导出用于备份或交换 |

首页的当前金币／收入／剩余人口／当前生命只改当前状态，不是存档，当前选兵也是本局操作。**双方招募与蓝方选兵 AI 开关在本局立即生效，并同步保存给后续新局**；首页与「自动行为（本局与下局）」编辑的是同一套开关。普通兵种／资源规则编辑不会顺带重置这些开关；载入完整预设、恢复默认或撤销则按对应设置恢复。下调收入上限不当场扣减当前收入，招募增加收入时才按上限处理；人口额度在下一轮结算重置时使用，不立刻改变本轮剩余人口。

本局摘要分别显示实际难度和规则状态。仅选择不可战胜等难度、未改规则，仍是原版规则；修改参数后可同时显示“不可战胜”与“自定义”。AI 菜单只选择编辑哪一档、哪一类和哪张候选表，不改变本局难度。

### 自动应用、本机保存与命名预设

**改完确认即可，不需要两次提交。** 有效数字按 Enter 或离开输入框确认，选择／开关在变更后提交；空白、尚未完成或非法输入不会覆盖正在使用的有效参数。可在本局生效的规则自动应用，开局项自动排到下一局。没有正在进行的对局时，设置留给下次开局，不会自动开始战斗。

旧版「草稿未保存」比较的是当前内容与最近载入／保存预设时的编辑基准，而不是磁盘写入状态；旧版修改也会尝试保存本机备份，且不同页面的生效方式不一致。这就是看见“未保存”却有的参数已生效的原因。新版不再显示这个概念：**「本机保存中…」「已保存到本机」「本机保存失败 · 可导出备份」**直接反映保存状态；尚未确认输入显示「输入待确认（Enter / 离开确认）」。

| 操作 | 作用 |
|---|---|
| 确认兵种／通用规则／AI 参数 | 自动应用当前可生效项、更新后续规则并保存到本机 |
| 确认开局专用参数 | 自动保存并用于下一局，不重开本局 |
| 撤销上次设置 | 恢复上一份设置并实际应用，最多 30 次；不回滚军队、金币、随机状态或战局进度 |
| 恢复原版默认 | 恢复全部面板参数并实际应用；开局项下局生效；不清兵、不删预设、不自动开新局 |
| 按当前设置开始新战局 | 确认后结束本局，使用当前设置及所选模式、难度开始新局 |
| 返回主菜单（结束本局） | 确认后结束本局、返回菜单；保留当前设置与预设，不等于恢复默认 |
| 另存为新预设／覆盖预设 | 保存当前规则的命名副本，方便以后切换；不是生效所必需 |
| 载入并应用／导入并应用 JSON | 验证后自动应用并保存；开局项仍留到下一局 |
| 导出 JSON | 导出当前设置作备份或交换；不是战局存档 |

「恢复原版默认」恢复面板参数，不撤销此前批准的弹道命中／延寿改进，也不改写外置 `config/custom.json`。重置还会把本局双方招募与蓝方选兵 AI 恢复为开启；可热改的默认规则立即生效，不补金币、不清空军队、不重置倒计时与已在进行的冷却；已飞出的攻击保留创建时的弹道和剩余寿命。时间倍率、暂停和镜头是本次运行控制，不属于规则预设。

### 应用内确认

针对恢复默认后输入框无法继续编辑的反馈，恢复默认等需确认的设置操作改用应用内异步确认框，不使用原生阻塞确认窗口。**默认焦点在「取消」**；按 Esc 或点取消不执行操作。明确确认后关闭确认框，目标是无需重启或切换其他窗口，即可继续点击参数框、键盘输入及确认修改。已发布 0.7.2 正式 EXE 已验证确认、取消、Esc 取消、全屏及连续恢复后的真实键盘编辑；不据此断言旧问题已确定唯一原因或覆盖全部环境。

确认框只改变操作确认方式，不改变参数值含义、生效时机、自动保存、预设、撤销或恢复默认的范围；用户已确认保留的弹道命中和延寿改进仍保留。

### 时间、取整与生命

- **30 逻辑帧 = 1 游戏秒**；轮长、命中延迟以游戏帧计，不是现实毫秒。倍速改变等待时间，不改规则帧数。
- 生效移速 = 基础移速 × 移动倍率；生效射程 = 基础射程 × 射程倍率。兵种攻击冷却 = `Math.trunc(基础攻击间隔 × 攻击间隔倍率)` 帧。极端结果按数值安全边界饱和，已有冷却不重置。
- 费用、人口消耗、招募增加收入影响后续招募，不退还之前花费；命中延迟用于新投射物。当前轮次倒计时不重置，后续轮长在下一轮使用。
- 界面更新生命上限时统一保持生命比例，不提供策略下拉框；不复活死亡单位，保留原版可能出现的超额生命。水晶当前生命仍可单独改，已毁水晶不能靠此复活，需开新局。开发 API 的 `health: 'absolute'` 仍保留，但不是面板选项。
- 实际攻击还受目标、动作和命中延迟影响，不把冷却字段包装成固定实际攻速。

## 数值范围与自动收束

| 类型 | 范围 | 规则 |
|---|---|---|
| 金币余额、每轮收入、人口、费用、AI 数量／资源阈值 | 0～**9,007,199,254,740,991** | JavaScript `Number.MAX_SAFE_INTEGER`，不再人为限制到一亿／一万 |
| 刷兵数量 | 1～**9,007,199,254,740,991** | 是实际生成的士兵个数，不是人口消耗；无额外 100／500 限制 |
| 轮长、招募检测间隔、水晶冷却、主力最低数量 | 1～安全整数上限 | 正整数语义保留，避免零取模等无效规则 |
| 命中延迟 | 0～安全整数上限 | 游戏帧整数 |
| 生命、伤害、护甲、距离、移速、倍率等浮点字段 | 不超过 `Number.MAX_VALUE`（约 1.7976931348623157e308） | 一般非负；生命上限必须正数，最小正值为 `Number.MIN_VALUE`（5e−324） |
| 概率／护甲类型／兵种 ID | 0～1／0 或 1／0～15 | 这是字段意义，不是人为沙盒额度 |
| 游戏倍率 | 0～100，步进 0.1 | 明确的时间控制范围，与资源整数范围无关 |

输入完整数字超过上限时，**输入框立即固定到最大值**；例如金币输入 `1e999` 会显示 `9007199254740991`。下界与整数取整在提交时收束，避免把输入 `0.5` 的中间状态强行打断。空白、非数字文本仍需补全；非法候选集合仍会提示。JSON 导入是文件验证，不是输入框，会严格拒绝超范围或未知字段，避免悄悄改写预设含义。

「金币上限」在此明确叫**每轮收入上限**，不是持有余额上限。余额没有新增玩法封顶，只在安全整数处饱和。自定义运行层用精确整数中间运算再转回 Number，避免累加后溢成负数或先舍入丢掉一个金币；浮点运算溢出时保持有限值。这不意味着极端浮点数具有无限精度或一定形成有意义的玩法。

## 生成与清场

- 选择兵种、输入数量，直接点「生成红方士兵」或「生成蓝方士兵」。使用**当前生效**规则，不采用尚未确认或非法输入；免费生成，不扣金币／人口、不增加收入。
- **取消旧单次 100／总数 500 的限制。** 按小批次生成，让出事件循环，显示已完成／剩余数量；「取消剩余生成」只取消尚未生成部分，已生成士兵保留。
- 「清除红方士兵」「清除蓝方士兵」「清除双方士兵」三个直接按钮，无确认窗口。点击后存活士兵走原 `dead()` 流程：生命归零，立即退出战斗与寻敌名单，但仍留在场景中播放原死亡后仰／倒地动画，不再瞬间消失。
- 水晶不受伤，相关攻击物清除，不退款、不可撤销；同时取消匹配阵营未完成的生成任务，避免刚清完又补回来。重复清场不重新触发已有尸体的死亡事件或重置倒计时。
- 动画沿用原逻辑时钟：默认 `deadTime = 25`，每次该尸体自身得到处理时减 1，到 1 时移除，即默认第 **24 次自身处理**后离场。30 Hz 是全局频率；动态列表处理顺序可能跳过个别对象，不能把它说成固定现实秒数。倍速影响播放等待；暂停、0 倍或其他阻止逻辑推进的状态下，动画等恢复后继续，清场不会强行启动时钟。
- 保留原死亡事件与随机死亡音效选择，现有音频层合并同批次音效；不添加新素材，也不修改正常战斗死亡规则。
- 新局、返回主菜单、对局结束或生成方水晶已毁时停止旧任务。暂停不阻止明确的沙盒操作，因而可以在静止战场上布置士兵。
- **取消额度不等于无限性能。** 原战斗的寻敌／分离等包含随兵量近似二次增长的扫描；极大兵量仍可能卡顿或耗尽内存。分批只避免一次创建循环长期霸占线程，不能中断一个已经很慢的完整战斗步，也不保证取消瞬时响应。

原版没有建筑建造、主动技能、固定波次或条件增援系统，不虚构这些入口。

## 双 AI 对战

首页点击「双 AI 对战」，分别为「红方 AI」「蓝方 AI」选择简单、普通、困难或不可战胜，再点「开始对战」。设置面板「开局设置」也可选择第三种模式「双 AI 对战」，调整两侧档位及数值选项后按当前设置重新开局。原来的单人／同机双人模式保持原行为；双 AI 是明确启用的新自定义模式，不是给原版菜单暗中换规则。

- **双方都使用原有选兵算法**，不是学习模型。每次收入结算先处理原金币／人口刷新，然后红方 AI、蓝方 AI 依次决策，再按原招募流程出兵；双方各看对方兵种与自己的金币／收入。共享原随机数流，顺序固定为红后蓝，不保证把阵营对调后随机结果完全镜像。
- **可手动干预**：点击兵种或用红方 WASD／蓝方方向键选择，AI 到下一次收入结算才重新接管，并非立刻覆盖。场上单位移动、寻敌、攻击仍按原规则。
- **「暂停出兵／开始出兵」只控制对应阵营的自动招募**，不清兵、不冻结已有单位，也不停止该侧下一轮 AI 选兵。全局暂停／0 倍才停止战斗时钟及收入结算；U／O 观察缩放仍可使用。双 AI 中双方选兵 AI 固定启用，旧「蓝方 AI」开关不适用；其已保存值不会因此被改写。
- **难度属性选项分清用途**：「同时使用所选难度的数值加成」默认勾选；勾选时，每侧套用自己所选难度的开局收入、开局剩余人口、水晶伤害与冷却；未勾选时，这四项双方都用**当前配置的普通档**（仍包含用户对普通档的修改），仅选兵策略保留所选难度。普通兵属性、水晶生命／射程、开局金币仍保留各侧自定义，并不统一乘某个难度倍率。

### 镜像难度默认参数

下表来自 `config/defaults.generated.json` 与 `src/customization/runtime.mjs` 的实际字段，列的是**无自定义覆盖、启用难度数值时该侧的基础值**；红蓝都用同一张表，禁用数值联动则都取普通行的四项属性。当前保存的配置可能覆盖这些值，实际以面板与战局状态为准。

| 该侧 AI 难度 | 反制分支概率 | 开局收入 | 开局剩余人口 | 水晶伤害（轻／重） | 水晶冷却参数 |
|---|---:|---:|---:|---:|---|
| 简单（0） | 0% | 500 | 80 | 100／100 | 30 逻辑步（1 游戏秒） |
| 普通（1） | 50% | 500 | 80 | 100／100 | 30 逻辑步（1 游戏秒） |
| 困难（2） | 100% | 500 | 80 | 100／100 | 30 逻辑步（1 游戏秒） |
| 不可战胜（3） | 100% | 600 | 100 | 110／110 | 25 逻辑步（25/30 游戏秒） |

默认开局金币 **0**、水晶生命 **3500**、射程 **600 世界单位**；首轮等待 **180 逻辑步**，后续每 **900 步**结算。每游戏秒 **30 步**，倍速只改变现实等待时间。开局 100 人口不是永久上限：第一次及以后结算都会恢复公共 `populationLimit`（默认 **80**）。默认 0 金币时，首次获得收入之前已重置到 80，不能把 100 宣传成每轮多 20 人。表中冷却是配置参数，不保证有目标／距离／动作条件下始终以固定频率命中；整数步与分数秒按上述比值表达，不另造固定兵种攻速。

**同档参数共享**：双方用同一有效数值难度时，编辑该档水晶伤害／冷却会影响双方；不是独立复制出两份难度配置。水晶生命／射程与兵种仍可按阵营编辑。双 AI 模式选项属于当前运行／战局，不写入规则预设或当前参数文件；命名预设保存的是原有可编辑规则，而非 AI 对战录像或战局进度。

开发入口：`controller.startAIMatch({ leftDifficulty, rightDifficulty, applyDifficultyStats })`，或 `customization.startBattle({ mode: 'ai-vs-ai', dualAI: { ... } })`。`src/extensions/dual-ai.mjs` 安装收入结算钩子；`snapshot.dualAI` 提供双方有效数值档、决策次数与出兵状态。重开保持本次模式选项；返回菜单选择原单人／双人不会沿用双 AI 钩子。

## AI 选兵逻辑与可调参数

AI 在**单人模式每轮收入发放后**选下次招募兵种。它不是学习模型，不会因你改了伤害／护甲就自动生成新的克制表；关闭蓝方 AI 选兵只停止选兵，不冻结现有士兵寻敌、移动和攻击。

四档的默认反制概率依次为 **0、0.5、1、1**。开局蓝收入为 **500、500、500、600**，首轮人口为 **80、80、80、100**；后续仍按通用人口额度重置。水晶与基础兵种默认表见[参数表](parameters.zh-CN.md)。

每档字段位于导出设置的 `profile.config.difficulties.<0–3>.ai`，概率在同级 `counterSelectionProbability`：

| 阶段／字段 | 默认逻辑与数值 | 可改内容 |
|---|---|---|
| 进入反制分支 | 难度概率 `> rng()` | 四档概率各自独立 |
| `counterMinimumCount` | 至少 2 个才参与主力选择，取数量最多的红方兵种 | 最少数量；不把水晶算作兵种 |
| `newbieIncomeThreshold` 与两个 `newbie*Choice` | 主力为 0 时：蓝收入 `<200` 选 0，否则选 3 | 收入阈值及两种选择 |
| `counterChoices.<1–15>` | 对主力 ID 查候选列表，等概率随机；空列表走后备分支 | 各主力的反制候选集合 |
| `counterFallbackIncomeThreshold`、`counterFallbackChoices`、`counterFallbackLowIncomeChoice` | 无有效反制表：蓝收入 `>1000` 从 0～15 随机，否则选 0 | 阈值、高收入候选、低收入固定选择 |
| `randomIncomeThreshold`、`randomHighIncomeChoices`、`randomLowIncomeChoices` | 普通分支：蓝收入 `>450` 从 0～13 随机，否则从 0～7 随机 | 阈值与两个候选集合 |
| `forceMoneyEnabled`、`forceOverlordMoneyThreshold` | 默认启用；蓝方**余额 >15030** | 开关和严格大于的阈值 |
| `forceEliteEnabled`、`forceOverlordEliteCountThreshold`、`eliteUnitIds` | 默认启用；红方 14／15 号合计 **>2** | 开关、数量阈值、统计哪些兵种 |
| `eliteCountOnlyCounterBranch` | 默认 true，只在本次进入反制分支时统计上述精英 | 关闭后普通随机分支也统计 |
| `forcedUnitId` | 两条已启用强制条件任一满足，最后覆盖为 15（大领主） | 最终强制兵种 ID |

阈值 `>15030`、`>2`、`>1000`、`>450` 都是**严格大于**；恰好相等不满足。新兵分支是 `<200`，恰好 200 走另一侧。默认精英条件不是“两万士兵”，而是**超过两个**特定兵种。主力统计沿用阵营列表，尚未从列表移除的死亡动画也可能被计入；并列主力沿用原遍历／平局处理，不保证跨 Flash 运行时完全相同。

## 预设、兼容与备份

最多 25 个命名预设，名称 1～80 字符；单个导入文件最多 256 KiB，预设库最多 2 MiB。这些是文件／存储安全边界，不是军队或资源上限。只接受白名单 JSON，不执行脚本。

| 位置 | 内容 |
|---|---|
| 桌面 `userdata/custom-settings.json` | 当前设置与命名预设，通过受限 IPC 写入，不依赖每次本地服务端口；成功保存的设置在重启时自动恢复 |
| 浏览器 `localStorage` | 按当前站点来源保存；换地址／端口或清站点数据会改变可用存储 |
| 包外 `config/custom.json` | 启动覆盖，面板不改写；不要用面板导出 JSON 直接覆盖它 |
| 面板导出 JSON | 可迁移设置，通过面板导入并应用，不是战斗进度存档 |

本机当前设置的新保存封套为 `schemaVersion: 2`，同时记录 `template`，使重启保持配置模板选择；有效的旧 v1 本机草稿也会自动恢复。设置内部 `profile.schemaVersion` 为 **2**；导出外壳和预设库版本仍为 **1**。旧 v1 设置／预设可读取迁移：原共享兵种、水晶生命／射程、开局金币复制给两方，旧难度资源保留，补充原默认 AI。存储键名保持兼容。新设置改一方不再改另一方；旧共享路径保留给旧集成，不是新界面的编辑方式。

**配置优先级：**启动先读取 `config/custom.json`，再恢复本机保存的面板设置，因此保存值会覆盖启动文件中的同名面板参数；未暴露的字段继续来自启动模板。开发 API 若保存过 `template: "original"`，则使用恢复的原版模板。要重新采用启动文件全部面板值，先退出游戏并备份，再仅移除 `miragine-custom-draft-v1` 当前设置记录；不要删除 `miragine-custom-presets-v1` 命名预设库，也不要直接删除整个 `userdata/`。

成功保存的当前设置在重启时自动恢复，载入预设也会自动应用；但这些文件不保存当前军队、当前资源、随机数或战斗进度。速度、暂停、显示上限和镜头不进规则预设，启动默认 1 倍。保存失败会警告，内存中的有效设置仍可导出；桌面写入须后端确认，不能把内存修改成功当作已经落盘。升级前备份两个自定义文件，重要设置另存命名预设并额外导出 JSON，是最便捷的备份／切换方式。重新提取／生成不会覆盖这些人工配置。
