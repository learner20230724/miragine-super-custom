# 超级版参数与实际生效规则

[English](parameters.en.md)

本文以本项目保存的**超级版**原始 SWF 和恢复的 AS3 为准，不采用 JKS 或普通版的重写数值。`config/defaults.generated.json` 保存原始字段、实际换算值和动画映射；`generated/config-provenance.json` 保存源文件哈希、逐兵种字段行号和语义说明。静态提取与测试通过不等于已经完成整局逐帧对照。

## 如何修改而不被重新生成覆盖

只在 `config/custom.json` 的 `overrides` 内填写需要改动的值；其余值继承默认配置。例如：

```json
{
  "schemaVersion": 1,
  "profile": "custom",
  "overrides": {
    "units": {"0": {"cost": 15, "hp": 60}},
    "rules": {"incomeLimit": 10000},
    "difficulties": {"3": {"rightStartingIncome": 650}}
  }
}
```

`units` 的键是稳定的菜单兵种 ID 字符串 `"0"` 至 `"15"`，不是动画编号 `ss`。数组（例如 `damage`）需要整体填写。`unit.runtime` 与 `unit.animation` 只记录默认配置的派生结果；改变原始属性后，引擎必须重新换算，不能再使用旧值。自定义 `ss` 后根据 `animations` 中的真实符号读取帧数；普通兵动作速度 / 循环由 `rules.animationSpeeds` / `rules.animationLoops` 统一控制，基地和特效则采用各自 `animations` 项中的速度 / 循环。

```text
python -B tools/extract_game_config.py
python -B tools/extract_game_config.py --check
node --test tests/extracted-config.test.mjs
```

生成器只写 `config/defaults.generated.json` 与 `generated/config-provenance.json`；`--check` 完全只读。不会改 `custom.json`、扩展代码或恢复源码。

## 移速、射程、攻击间隔与动画

来源：[DragonForce.createUnit](../recovered/as3/scripts/DragonForce.as)、[Isometric2DEntity](../recovered/as3/scripts/dragonforce/isometric2D/Isometric2DEntity.as)、[Symbol](../recovered/as3/scripts/dragonforce/core/Symbol.as)。

- `moveSpeed × 1.3` = 世界坐标单位 / 模拟帧，**不是屏幕像素 / 秒**。
- `range × 60` = 水平方向世界坐标单位；同时还要求纵向距离不超过 40。
- `weaponSpeed × 20` 赋给整型冷却计数 `t`，**向零截断**；表中正数相当于向下取整。原始 `weaponSpeed` 不是秒。
- 秒数仅为「冷却帧数 ÷ 30」的名义值，下表显示到小数点后 6 位；实际墙钟耗时取决于运行帧节奏。JSON 保留完整双精度换算值。
- `delayAttack` 是攻击物开始移动前的延迟帧数，不是动作总长度。即使近战也沿用移动攻击物的命中逻辑；不能以动画总帧数推导固定攻击频率。

## 经济、回合与基地

所有下表路径均相对于 `rules`；帧数按名义 30 FPS 理解。实际来源为 `DragonForce.init/step`，不是被初始化逻辑覆盖的类字段初值（例如字段收入 100 会被 `init` 改成 500）。

| 参数 | 默认值 | 单位与实际含义 |
|---|---|---|
| frameRate | 30 | 模拟帧 / 名义秒 |
| mapWidth / mapHeight | 4500 / 800 | 世界坐标单位 |
| initialMoney / startingIncome | 0 / 500 | 初始金币 / 每回合收入 |
| incomeLimit | 8000 | 每次招募增长后的收入上限，不是金币上限 |
| populationLimit | 80 | 每回合可消费人力预算；死亡不返还 |
| initialRoundFrames / roundFrames | 180 / 900 | 首次结算倒计时 6 秒；此后每回合 30 秒 |
| recruitEveryFrames | 3 | 招募开启时，倒计时模 3 为 0 就尝试购买所选兵种 |
| movementMultiplier / rangeMultiplier / weaponSpeedMultiplier | 1.3 / 60 / 20 | 原始兵种属性的运行时倍率 |
| baseHp | 3500 | 两边基地 nowHP 与 maxHP |
| baseDamage | [100,100] | 对轻 / 对重伤害，难度 3 蓝方另有覆盖 |
| baseWeaponSpeedFrames / baseRange | 30 / 600 | 基地攻击冷却帧数 / 水平世界距离 |
| baseSpawnInset / spawnJitterY | 300 / 200 | 出生点距边界；兵种纵向位置为 mapHeight/2 + 200 - 400×random |
| gameOverDelayFrames | 30 | 基地死亡后胜负事件倒计数初值 |

购买立即扣除金币和本回合人力，立即增加下一次结算可领的收入。结算时先把双方人力恢复 `populationLimit`，再把当前收入加到金币，再将倒计时设为 900；单人 AI 随后重新选兵。不是「每回合只发一队兵」，也不存在预设敌人波次。

## 难度：确切变化，而不是笼统倍率

单人游戏每次 AI 决策先检查 `反制概率 > random()`。反制分支根据我方数量最多且超过 1 个的兵种选择反制列表；具体选择仍有随机性。没有证据表明提高难度会统一增加普通兵 HP、伤害或移速。

| ID / 名称 | 反制分支概率 | 蓝方初始收入 | 蓝方初始人力字段 | 蓝基地伤害 | 蓝基地冷却 |
|---|---:|---:|---:|---|---|
| 0 简单 | 0% | 500 | 80 | 100 / 100 | 30 帧（1 秒） |
| 1 普通 | 50% | 500 | 80 | 100 / 100 | 30 帧（1 秒） |
| 2 困难 | 100% | 500 | 80 | 100 / 100 | 30 帧（1 秒） |
| 3 不可战胜 | 100% | 600 | 100，首次结算即回 80 | 110 / 110 | 25 帧（0.833333 秒） |

难度 3 的实际额外变化：初始收入 **+20%**，基地伤害 **+10%**，基地攻击周期从 30 降到 25 帧（周期约 **−16.67%**，攻击频率 **+20%**）。初始 100 人力并非全程人口 +25%；默认初始金币为 0，首次发钱前人力已经重置到 80，因此这 100 在默认正常流程中不会形成可花费的额外预算。

`difficulties` 下可覆盖 `counterSelectionProbability`、`rightStartingIncome`、`rightStartingPopulation`、`blueBaseDamage`、`blueBaseWeaponSpeedFrames`。原 `init` 的难度 3 分支只检查难度值，不检查单人 / 双人模式，修改启动方式时不要悄悄改变这一条件。

### AI 反制与阈值

`ai.counterChoices`（键 = 我方主力 ID，值 = 蓝方随机候选 ID）：

```json
{
  "1":[1,3,5], "2":[4,6,7,8], "3":[4,7], "4":[1,6,8],
  "5":[3,10], "6":[5,6,12], "7":[4,8,9], "8":[5,6,12],
  "9":[6,8,9,11], "10":[11,13,14], "11":[8,9],
  "12":[9,10,12,13], "13":[8,9,11], "14":[9,10,11], "15":[9,10,11]
}
```

- 主力 ID 0：右收入 **<200** 选 0，否则选 3（`newbieIncomeThreshold` 等）。
- 无明确反制目标：右收入 **>1000** 时从 0–15 随机，否则选 0（`counterFallback*`）。
- 未进入反制分支：右收入 **>450** 时从 0–13 随机，否则从 0–7 随机（`random*`）。
- 右金币 **>15030**，或本次反制分支统计到的我方 14/15 号兵总数 **>2**：强制选 15（`forceOverlord*`、`eliteUnitIds`、`forcedUnitId`）。边界全为原代码严格比较，不是 `>=`。
- 相同数量的兵种遇到 Flash `Dictionary` 遍历顺序时，选择顺序存在运行时差异；不可声称不同运行时使用同一个随机种子就必然整局逐帧相同。

## 不适用机制（N/A）

依据 [DragonForce.as](../recovered/as3/scripts/DragonForce.as) 的 `initUI`、`P1Control` / `P2Control`、`createUnit` 与 `step`。下列项目不应凭其他策略游戏的惯例补成原版参数：

| 项目 | 原版状态 | 实际约束 / 应查看的参数 |
|---|---|---|
| 独立训练队列、每兵种训练耗时 | N/A；没有该系统 | 招募开启且回合倒计时满足 `round % recruitEveryFrames === 0` 时才尝试购买；默认值为 3，正常倒计时期间每 3 帧尝试一次。这不是每个单位的训练时长或独立冷却。金币和本回合人力充足时立即创建单位；任一不足都不能产生单位。 |
| 科技、建筑或升级解锁前置 | N/A；16 个兵种初始均可选择 | 选择不等于购买成功；每次招募仍须满足该兵种的 `cost` 与 `population`。 |
| 独立玩家主动技能、技能资源消耗、技能冷却 | N/A；没有该系统 | 兵种自动攻击及其特效不是玩家施放技能；`weaponSpeed`、`delayAttack` 与攻击物参数属于普通攻击机制，不能标成玩家技能冷却或技能费用。 |

初始帮助的 `stopTimer` 只停回合倒计时，不停引擎，因此上述取模条件不能理解为无条件的固定招募冷却。默认初始金币为 0，资金不足时不会出兵；此后仍逐次检查金币和本回合人力。

原游戏没有可配置的建造 / 建筑升级系统、玩家技能树或关卡波次。基地是固定战斗单位，不应把它的存在说成原版具有建筑生产系统。此类新玩法只能作为独立、默认关闭的扩展加入。
