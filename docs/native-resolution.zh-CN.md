# 原生窗口分辨率绘制

[English](native-resolution.en.md) · [设置](custom-settings.zh-CN.md) · [时钟](time-control.zh-CN.md)

本文描述 v0.5.0-preview.1 的源码实现，不代替该版本的发布、实机验收或性能报告。原游戏规则、参数、30 Hz 逻辑和原始素材不变；只让现有绘图流程直接使用窗口需要的像素数量。

## 改了什么

过去先完成一张 640×480 舞台位图，再把整张图拉大到窗口，即使角色来自原 PNG，中间成图仍限制了大屏细节。现在可见画布本身就是最终绘图目标；先设置逻辑→实际像素的绘图变换，再绘制地面、角色、菜单与 HUD，不经过那张最终被放大的低分辨率舞台图。

| 层次 | 坐标／尺寸 | 是否改变原规则 |
|---|---|---|
| 舞台布局与点击区域 | 640×480 逻辑坐标 | 不变 |
| 战场投影 | 640×400 逻辑区域，保留斜视角 | 不变 |
| 主画布 CSS 大小 | 按可用空间等比例适配，设置面板单独占位 | 只影响显示大小 |
| 主画布实际像素 | CSS 宽高 × `devicePixelRatio`，分别取整 | 只影响绘图目标密度 |
| 地面／HUD 缓冲 | 根据主画布实际像素密度创建 | 只影响栅格化与缓存 |
| 战斗模拟 | 每游戏秒 30 个完整逻辑步 | 不变；240 FPS 仍是独立显示目标 |

绘图缩放使用**取整后的实际画布尺寸**除以 640／480，不假设 `CSS 缩放 × DPR` 一定刚好是整数像素。窗口缩放、全屏、设置面板开关或移到不同 DPR 的屏幕时会更新尺寸。暂停时也会重绘新尺寸，但不会因此继续战斗或补算逻辑。

## 原 PNG 与细节边界

- 角色继续直接采样原 PNG，保持原脚点、逻辑尺寸、裁切、帧选择和绘制顺序；不生成新角色帧，不改动画速度。
- 山景、树木、草地和原特效图片不被重画、覆盖或 AI 放大。此前保留的 SWF 较大特效位图继续使用，不在本轮制造新纹理。
- 原素材中的轮廓可以直接映射到最终目标像素，不再受整张 640×480 中间图再次拉伸的限制；但**原图没有的细节不会出现**。极度放大的小角色仍可能像素化，低分辨率背景也不会自动变成高清绘画。
- Canvas／WebGL 的栅格化、滤镜与边缘仍不保证逐像素等同 Flash。更大的绘图目标不是 Flash 像素保真证明。

## 地面与 HUD 缓存

**地面：逻辑投影不变，实际栅格提高密度。** `GroundWebGLRenderer` 保留 640×400 投影坐标和透视正确 UVT 插值，只调整自身画布与 WebGL viewport 的实际尺寸。目标覆盖按像素边界取整，不偷偷改相机或纹理周期。无法分配所需地面尺寸时明确报错，不用隐藏的低分辨率回退伪装原生绘制。

**只缓存一个地面版本。** 跟随与自由观察使用同一个 `GroundLayerCache`；键包含实际尺寸、图像身份、精确相机与几何信息。命中时复用已投影结果；相机、图片或尺寸变化时覆盖旧条目，不为每个视角无限累积缓存。这里仍有 WebGL 画布和一张已投影 Canvas 缓存副本，不能理解为没有额外像素内存。

**HUD 按区域缓存。** 战斗静态 HUD 分为顶部／底部区域，血条保留两个固定槽，数字保留七个固定槽，不按每个新数值累积画布。缓存边界按目标像素对齐，再以对应逻辑位置合成，避免先画低分辨率 HUD 再放大。菜单／结算需要的较大缓存仍可能存在；resize 或页面切换时清零旧缓存画布并释放引用，防止旧尺寸缓冲一直保留。

本轮进一步缩小原生密度绘图中的无效工作，不靠降低分辨率：

- **标题菜单组件化**：父级阴影／滤镜仍按原效果执行，但目标裁成对应组件的小画布；保留原滑动、遮罩与颜色变换。切换音乐状态只影响音乐组件的小缓存，不重建整张标题页。
- **静态 HUD 直接按原放置项绘制**：保留原符号、顺序和完整放置矩阵，避免调用父容器时，已隐藏的数字仍触发空的全图滤镜处理。
- **选兵光标左右各一个局部槽**：按主画布相同的原生像素密度绘制完整原 `sprite209`，保留原时间、缩放脉冲和子元素透明度；状态相同时复用，变化时更新，不累积每帧画布，也不放大低分辨率成图。
- **背景只画可见原图块**：以有限的 `drawImage` 重复图块替代大变换下的 `CanvasPattern`，保留原 PNG、重复周期、平移锚点、裁切区域与最近邻采样；不扩大源图、不生成低分辨率背景缓存。这里只描述实现，不宣称不同原生绘图路径逐像素完全一致。

这些改动位于手工运行适配层，不改原生成绘图文件、原素材、核心规则或 30 Hz 逻辑。实际性能变化须看本轮同条件实测，不能仅凭缓存结构推断提速比例。

局部透明层合成和 Canvas 采样可能使少量边缘抗锯齿与未优化的原生试验版出现细微差异；这不代表原素材被修改，也不宣称优化前后逐像素完全一致。

增加像素数会增加绘制和显存／内存压力；缓存减少重复工作，不等于总内存一定下降，也不保证高 DPR、4K 或巨量军队下保持原帧率。

## 输入为什么不乘 DPR

浏览器指针位置和 `getBoundingClientRect()` 都以 CSS 像素表示。输入先减去画布的 CSS 位置，再按实际显示宽高映射到 640×480 逻辑坐标。DPR 已用于绘图缓冲，**不能再次乘到鼠标坐标上**，否则在高 DPI 屏幕会点偏。

滚轮缩放、拖动、菜单热点和兵种选择继续走相同逻辑坐标映射；显示比例变化不改变地图范围、移动速度或兵种战斗属性。

## 开发入口

| 文件 | 职责 |
|---|---|
| `src/platform/viewport.mjs` | 等比例 CSS 布局、取整后的 backing 尺寸及 CSS→逻辑输入转换 |
| `src/app/main.mjs` | 可见画布直接作为最终目标；resize／DPR 更新与暂停重绘；只读呈现统计 |
| `src/app/view.mjs` | 原逻辑坐标下绘制 UI；原生密度缓存、紧凑区域与旧缓冲释放 |
| `src/render/battlefield.mjs` | 传递目标密度，角色原图直接绘制，精确单项地面缓存键 |
| `src/render/ground-webgl.mjs` | 原 UVT 投影的原生像素栅格与目标尺寸检查 |
| `src/render/ground-layer-cache.mjs` | 单条目缓存，尺寸变更时原位重设／失效，销毁时释放 |
| `tools/verify-native-resolution.mjs` | 实际交互、尺寸／输入／性能采样；源码或独立便携包 |
| `tools/verify-native-clarity.mjs` | 相同原图、相同投影的独立冻结画面比较，不是整局帧率测试 |

先启动开发服务器，再检查当前源码：

```sh
npm run dev
node tools/verify-native-resolution.mjs --url http://127.0.0.1:51286/ --mode native --out .local/native-resolution.json
node tools/verify-native-clarity.mjs --report .local/native-clarity-verification.json
```

独立便携包可用 `--dir <测试副本目录>` 替代 `--url`。比较旧版时使用 `--mode baseline` 和独立旧版测试副本，确保 Electron 版本、窗口、DPR、实际场景与采样条件一致。测试报告写入忽略目录；不要把本机路径或临时用户数据加入公开仓库。

## 如何理解验收结果

1. **尺寸与输入**：证明 backing 随窗口／DPR 更新、暂停仍重绘、点击坐标准确，不等于已经证明清晰度或性能。
2. **画面比较**：同原图同投影的截图／局部裁切有助于观察中间重采样差异；边缘能量等统计只是描述，不能单独证明“画质提升百分之几”。
3. **性能**：分清模拟步数、画面提交次数、RAF 回调和 CPU 提交时间；这些都不直接等于 GPU 完成时间或显示器实际刷新。旧版本短测数字不能替代本轮同条件测量。
4. **交付**：源码测试、实机交互、独立 ZIP 启动、源码／素材哈希、隐私检查和发布附件核验是不同步骤，结果以本版本记录为准。**240 FPS 与 20 倍仍是目标，不是保证。**
